## 三、实验整体逻辑分析

### 3.1 本章节的逻辑主线

本章围绕“让最小内核启动并输出一行文字”展开。本次没有新增内核功能，重点是理解已有代码，并通过实际运行验证启动链：

```text
源码 → 编译 → 链接为 bin/kernel → 生成 bin/ucore.img
     → QEMU 复位代码 → OpenSBI → kern_entry 设置栈
     → kern_init 初始化 → SBI 输出 → while (1)
```

### 3.2 功能的逐步实现

首先编译、链接源码，得到可加载的镜像。QEMU 在模拟 CPU 执行指令前，将 OpenSBI 和内核镜像分别加载到以 `0x80000000` 和 `0x80200000` 开始的内存区域。随后 CPU 从 `0x1000` 的复位代码开始执行，跳入 OpenSBI；固件完成初始化后，再把控制权交给内核。加载镜像和跳转执行是两个不同的步骤。内核入口必须先准备栈，C 函数才能保存寄存器和调用其他函数。最后执行初始化、输出启动文字并进入循环。这一顺序体现了内核运行所需环境的逐步建立。

| 核心模块或函数 | 作用及相互关系 |
| --- | --- |
| `Makefile` | 编译源码并调用链接器，生成带符号的 `bin/kernel`，再用 objcopy 生成裸镜像 `bin/ucore.img`。前者供 GDB 使用，后者供 QEMU 加载。 |
| `tools/kernel.ld` | 用 `ENTRY(kern_entry)` 指定入口，以 `0x80200000` 为链接起点，安排代码和数据的位置。 |
| `kern/init/entry.S` | 预留启动栈，设置 `sp`，跳转到 `kern_init`。 |
| `kern/init/init.c` 的 `kern_init` | 执行 `memset(edata, 0, end-edata)`，调用 `cprintf` 输出，最后进入 `while (1)`。 |
| `kern/libs/stdio.c` | `cprintf → vcprintf → vprintfmt` 格式化字符串，再经 `cputch` 逐字符输出。 |
| `kern/driver/console.c` 的 `cons_putc` | 将字符交给 `sbi_console_putchar`。 |
| `libs/sbi.c` 的 `sbi_call` | 将服务号和参数放入寄存器，执行 `ecall`，由 OpenSBI 完成控制台输出。 |

链接脚本安排代码和数据的内存布局，使内核入口与加载地址相对应。`kern_init` 中的 `memset(edata, 0, end-edata)` 用于清零相应的未初始化数据区域。

### 练习1：程序入口

**负责人：** 2413790-姜禧、2410250-张浩正（共同完成）。

**`la sp, bootstacktop`：** `sp` 是栈指针寄存器 `x2`。`bootstack` 为预留栈空间的起点，`bootstacktop` 为结束位置。栈向低地址增长，因此空栈从高地址端开始。该指令将栈顶地址写入 `sp`，为 C 函数保存返回地址、寄存器和局部数据准备空间。

本次入口反汇编为：

```text
0x80200000: auipc sp,0x3
0x80200004: mv    sp,sp
0x80200008: j     0x8020000a <kern_init>
```

前两条对应伪指令 `la`，得到 `sp=0x80203000`。其中 `mv sp,sp` 是 `addi sp,sp,0` 的别名，本次低位修正量恰好为 0。C 函数随后通过 `addi sp,sp,-16` 分配栈帧，说明进入 C 代码前确实需要设置栈。

**`tail kern_init`：** 将控制权交给 `kern_init`，本次链接后对应上面的 `j`。普通 `call` 会把返回地址写入 `ra`，而这次尾调用不建立返回到 `kern_entry` 的新返回地址。`kern_init` 最后进入 `while (1)`，本实验的运行流程不返回入口汇编。

### 练习2：使用 GDB 验证启动流程

**负责人：** 2413790-姜禧、2410250-张浩正（共同完成）。

#### 1. 启动调试并观察复位入口

在两个 WSL Ubuntu 终端中进入实验目录，分别运行 `make debug` 和 `make gdb`。QEMU 暂停模拟 CPU，并等待 GDB 连接。连接后输入：

```gdb
info registers pc
x/10i $pc
```

观察到 `PC=0x1000`。图2中的初始代码如下：

| 地址 | 指令 | 操作及目的 |
| --- | --- | --- |
| `0x1000` | `auipc t0,0x0` | 获取复位代码基址，将 `0x1000` 放入 `t0`。 |
| `0x1004` | `addi a2,t0,40` | 将 `0x1028` 放入 `a2`，设置供下一阶段使用的启动信息地址。 |
| `0x1008` | `csrr a0,mhartid` | 读取当前硬件线程编号，作为启动参数。 |
| `0x100c` | `ld a1,32(t0)` | 从 `0x1020` 读取设备树地址，放入 `a1`。 |
| `0x1010` | `ld t0,24(t0)` | 从 `0x1018` 读取固件入口地址，放入 `t0`。 |
| `0x1014` | `jr t0` | 跳转到 `t0` 中的地址，转入 OpenSBI。 |

图2使用 `x/3gx 0x1018` 查看启动数据，显示固件入口为 `0x80000000`。随后在该地址设置断点并继续运行，实际命中 OpenSBI 入口，验证复位代码把执行权交给固件。图1中的 `Firmware Base=0x80000000` 与此一致。

`x/10i` 只查看内存，不执行指令；数字 10 只是显示数量。图2中的复位代码包含上表中的六条指令。后面的 `unimp` 和 `0x8000` 是把地址数据按指令格式解码的显示，不能据此认为 CPU 跳到了 `0x8000`。

#### 2. 验证控制权到达内核入口

在内核入口设置断点并继续运行：

```gdb
b *0x80200000
c
info registers pc sp ra
disassemble /r kern_entry
```

图3显示 `PC=0x80200000 <kern_entry>`，证明 CPU 已到达内核汇编入口。入口反汇编包含 `auipc sp,0x3`、`mv sp,sp` 和跳转到 `kern_init` 的 `j` 指令，分别对应源码中的栈初始化和尾调用。此时 PC 位于第一条指令，入口指令尚未执行。

#### 3. 检查栈初始化并进入 C 函数

查看启动栈边界：

```gdb
p/x &bootstack
p/x &bootstacktop
```

图3显示 `bootstack=0x80201000`，`bootstacktop=0x80203000`。执行入口处的前两条指令后，查看寄存器：

```gdb
info registers pc sp
```

此时 `PC=0x80200008`，`sp=0x80203000`。栈指针与预定栈顶相等，说明栈初始化已经完成，下一条指令将跳转到 `kern_init`。

随后设置 C 初始化函数断点并继续运行：

```gdb
b kern_init
continue
info registers pc sp ra
```

图3命中 `kern_init` 断点，显示 `PC=0x8020000a <kern_init>`、`sp=0x80203000`，对应 `kern/init/init.c` 中的 `memset(edata, 0, end-edata)`。这验证了内核从汇编入口设置栈后，成功转入 C 语言初始化函数。

## 六、实验总结与收获

### 对操作系统的理解

| 实验知识点 | 对应原理及联系、区别 |
| --- | --- |
| 复位入口与 OpenSBI | 对应系统引导：固件先准备环境，再交给内核；固件不是 ucore，`0x1000` 也不是所有 RISC-V 机器统一的复位地址。 |
| ELF、裸镜像与链接脚本 | 对应程序装载和内存布局：链接地址要与加载方式配合；ELF 含符号等元数据，裸镜像不含这些结构。 |
| 内核栈与调用约定 | 对应函数调用和现场保存：C 函数依靠栈运行；本实验只有启动栈，尚无多个进程各自的内核栈。 |
| S-mode、SBI 与 ecall | 对应特权级和受控服务调用：内核请求固件服务，与用户程序向内核发起系统调用不同。 |
| 断点与单步 | 用机器状态验证执行顺序，是观察系统运行的调试手段，不是内核本身的功能。 |

本实验还未涉及进程与线程、调度、页表与虚拟内存管理、用户程序与系统调用、完整中断异常处理、文件系统和同步互斥。它们都需要建立在本次完成的启动基础之上。

### AI 协作开发的经验

通过本次实验，我们意识到使用AI辅助学习的时候，需要把自己的实验环境给说清楚，不同的 OpenSBI或工具链版本，可能使启动信息、反汇编结果和部分地址有所不同。因此不能照搬旧的实验文档，还是需要以当前编译结果为准，这样才能更好的使用AI来辅助我们学习。
